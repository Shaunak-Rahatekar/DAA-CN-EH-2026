Q1.1. Recurrence with Square Root: $T(n) = T(\sqrt{n}) + 1$
4 MARKS | FORECAST CORE
Problem: Solve the recurrence $T(n) = T(\sqrt{n}) + 1$ assuming $T(2) = 1$. Give the tightest asymptotic bound using variable substitution and recursion tree.
💡 Asli Baat: Har step pe power aadhi ho rahi hai ($n o n^{1/2} o n^{1/4} o \dots o 2$). Log lene par yeh normal binary search ($m o m/2$) ban jata hai, jiska solution $\log m = \log(\log n)$ hota hai!
Step 1: Change of Variables (Substitution)

Let $n = 2^m$, which means $m = \log_2 n$. Note that:

√n = n^(1/2) = (2^m)^(1/2) = 2^(m/2)

Now define a new function $S(m) = T(2^m) = T(n)$. Substituting $\sqrt{n} = 2^{m/2}$ into the original recurrence:

S(m) = S(m/2) + 1
Step 2: Solve the New Recurrence via Master Theorem

For $S(m) = S(m/2) + 1$, we have standard parameters $a = 1, b = 2, f(m) = 1 = m^0$.

m^(log_b a) = m^(log_2 1) = m^0 = 1 = Θ(f(m))

This matches Case 2 of the Master Theorem ($f(m) = \Theta(m^{\log_b a} \log^k m)$ with $k=0$):

S(m) = Θ(log_2 m)
Step 3: Back-Substitution to Original Variable $n$

Substitute back $m = \log_2 n$:

T(n) = S(log_2 n) = Θ(log_2(log_2 n)) = O(log log n)
Step 4: Recursion Tree Verification

At depth $k$, the argument size is $n^{1/2^k}$. The recursion terminates when $n^{1/2^k} \le 2$:

1/2^k · log_2 n = log_2 2 = 1 ==> 2^k = log_2 n ==> k = log_2(log_2 n)

Since each level contributes $O(1)$ work, total work = $\sum_{i=0}^k 1 = k + 1 = \mathbf{\Theta(\log \log n)}$.

⚠️ Exam Pitfall: Never leave the answer as $\Theta(\log m)$. You must explicitly substitute back $m = \log_2 n$ to get $\Theta(\log \log n)$.

3 MARKS | FORECAST CORE
Problem: Solve the recurrence $T(n) = 3T(n/2) + n$ using the Master Theorem. State the exact case and formal condition with $\epsilon$.
💡 Asli Baat: Subproblems ka count $a=3$ hai aur size divide ho raha hai $b=2$ se. Watershed exponent $n^{\log_2 3} pprox n^{1.585}$ root work $n^1$ se bada hai, isliye subproblems dominate karenge (Case 1)!
Step 1: Identify Master Theorem Parameters

In standard recurrence $T(n) = a T(n/b) + f(n)$:

a = 3, b = 2, f(n) = n
Step 2: Compute Watershed Critical Exponent
n^(log_b a) = n^(log_2 3) ≈ n^1.58496
Step 3: Compare $f(n)$ with $n^{\log_b a}$

Compare $f(n) = n^1$ with $n^{\log_2 3} pprox n^{1.585}$:

Choose ε = log_2 3 - 1 ≈ 0.585 > 0 Then f(n) = n^1 = O(n^(log_2 3 - ε)) = O(n^(1.585 - 0.585)) = O(n)

This strictly satisfies Case 1 of the Master Theorem.

T(n) = Θ(n^(log_b a)) = Θ(n^(log_2 3)) ≈ O(n^1.585)

Q1.4. Comparison-Based Sorting Lower Bound via Decision Tree Model
5 MARKS | HIGH PROBABILITY PROOF
Problem: Prove formally using the Decision Tree model that any comparison-based sorting algorithm requires $\Omega(n \log n)$ comparisons in the worst case.
💡 Asli Baat: $n$ numbers ko sort karne ke total $n!$ possible outcomes (leaves) hote hain. Har comparison binary decision (2 branches) deta hai. To height $h$ wale tree mein $2^h \ge n!$ hona compulsory hai, jisse $h \ge \Omega(n \log n)$ aayega!
Step 1: Decision Tree Abstraction

In any comparison-based sort, algorithms make 2-way branch decisions of the form $A[i] \le A[j]$:

  • Each internal node represents a comparison between two elements $A[i] : A[j]$.
  • Each edge represents the outcome of the comparison ($\le$ or $>$).
  • Each leaf node represents a distinct permutation of the original elements (the sorted output).
Step 2: Number of Leaves Bound

For an array of $n$ distinct elements, there are $n!$ possible input orderings. The sorting algorithm must be able to produce every single one of these $n!$ permutations. Hence:

Number of leaves L ≥ n!
Step 3: Height vs Leaves Relationship

A binary tree of height $h$ has at most $2^h$ leaves. Therefore:

2^h ≥ L ≥ n! ==> h ≥ log_2(n!)

The height $h$ of the decision tree represents the longest path from root to leaf, which is the worst-case number of comparisons.

Step 4: Bounding $\log_2(n!)$ Algebraically
log_2(n!) = sum_{i=1}^n log_2 i ≥ sum_{i=ceil(n/2)}^n log_2 i ≥ sum_{i=ceil(n/2)}^n log_2(n/2) = (n/2) · (log_2 n - log_2 2) = (n/2) · (log_2 n - 1) = (n/2) log_2 n - (n/2) = Ω(n log n)
Conclusion

Since $h \ge rac{n}{2} \log_2 n - rac{n}{2}$, we have $h = \Omega(n \log n)$. Thus, no comparison-based sort can run faster than $\Omega(n \log n)$ in the worst case.

Q1.5. Asymptotic Limit Comparisons: $n^{\log n}$ vs $2^n$ and $2^{\sqrt{\log n}}$ vs $\log n$
5 MARKS | RECURRING VIT CORE
Problem: Determine whether $f(n) = o(g(n))$, $\Theta(g(n))$, or $\Omega(g(n))$ with rigorous mathematical limit justification for:
(i) $f(n) = n^{\log_2 n}$ and $g(n) = 2^n$
(ii) $f(n) = 2^{\sqrt{\log_2 n}}$ and $g(n) = \log_2 n$
Part (i): $f(n) = n^{\log_2 n}$ vs $g(n) = 2^n$

Take base-2 logarithm of both functions:

log_2 f(n) = log_2(n^(log_2 n)) = (log_2 n) · (log_2 n) = (log_2 n)^2 log_2 g(n) = log_2(2^n) = n

Evaluate the ratio of logarithms as $n o \infty$ using L'Hôpital's Rule:

lim_{n -> inf} ((log_2 n)^2 / n) Applying L'Hopital (d/dn): = lim_{n -> inf} (2 log_2 n · (1 / (n ln 2))) / 1 = lim_{n -> inf} (2 log_2 n) / (n ln 2) Applying L'Hopital second time: = lim_{n -> inf} (2 / (n (ln 2)^2)) / 1 = 0

Since $\lim_{n o \infty} rac{\log_2 f(n)}{\log_2 g(n)} = 0$, it follows that $\lim_{n o \infty} rac{f(n)}{g(n)} = 0$.

Result: $f(n) = o(g(n))$ (Little-oh).

Part (ii): $f(n) = 2^{\sqrt{\log_2 n}}$ vs $g(n) = \log_2 n$

Let $k = \log_2 n$. Then $g(n) = k$ and $f(n) = 2^{\sqrt{k}}$.

Take logarithm of both with respect to variable $k$:

log_2 f(n) = sqrt(k) log_2 g(n) = log_2 k

As $k o \infty$, polynomial powers $\sqrt{k} = k^{0.5}$ strictly dominate logarithmic powers $\log_2 k$:

lim_{k -> inf} (sqrt(k) / log_2 k) = lim_{k -> inf} (0.5 k^(-0.5) / (1 / (k ln 2))) = lim_{k -> inf} 0.5 ln 2 · sqrt(k) = inf

Therefore $2^{\sqrt{k}}$ grows strictly faster than $k$.

Result: $f(n) = \omega(g(n))$ (or $g(n) = o(f(n))$).

Q2.1. Median of $k$ Sorted Arrays (Total Size $n$) in $O(k \log(n/k) \log( ext{Range}))$
6 MARKS | TOP FORECAST QUESTION
Problem: Given $k$ sorted arrays $A_1, A_2, \dots, A_k$ of total size $n$, design an efficient algorithm to find the overall median. Prove its time complexity is $O(k \log(n/k) \log( ext{Range}))$.
💡 Asli Baat: Direct merge karoge heap se to $O(n \log k)$ lagega jo slow hai jab $n$ bohot bada ho! Better approach: Answer (value) par Binary Search lagao. Range $[\min, \max]$ mein mid value guess karo aur har array mein binary search (`std::upper_bound`) se count karo kitne elements $\le ext{mid}$ hain!
Step 1: Algorithmic Insight (Value Binary Search)

Let $L = \min_{i} A_i[0]$ and $R = \max_{i} A_i[ ext{last}]$. The overall median is the element at position $\lfloor (n+1)/2 floor$ in the merged sorted order. We perform binary search over the value range $[L, R]$.

Step 2: Formal Algorithm
Algorithm MedianOfKSortedArrays(A[1..k], n): low = min(A[i][0] for i in 1..k) high = max(A[i][-1] for i in 1..k) target = floor((n + 1) / 2) while low <= high: mid = low + floor((high - low) / 2) count = 0 for i from 1 to k: count += CountLessEqual(A[i], mid) // Binary search in O(log(n/k)) if count < target: low = mid + 1 else: ans = mid high = mid - 1 return ans
Step 3: Complexity Analysis
  • Counting Subroutine: In each array of average size $m = n/k$, binary search takes $O(\log(n/k))$ time.
  • Total work per iteration: Across all $k$ arrays, counting takes $k imes O(\log(n/k)) = O(k \log(n/k))$.
  • Number of iterations: Binary search on range $[L, R]$ requires $\log_2(R - L) = O(\log( ext{Range}))$ iterations.
  • Total Time Complexity: $\mathbf{O(k \log(n/k) \log( ext{Range}))}$.
  • Auxiliary Space: $O(1)$ (no auxiliary arrays or heaps needed).
Q2.2. Median of Two Sorted Arrays of Equal Size $n$ in $O(\log n)$
5 MARKS | CLRS EX. 9.3-8 CORE
Problem: Given two sorted arrays $X[0..n-1]$ and $Y[0..n-1]$, each of size $n$, find the median of the combined $2n$ elements in $O(\log n)$ time using Divide and Conquer.
💡 Asli Baat: Dono arrays ke medians $m_1$ aur $m_2$ compare karo. Agar $m_1 < m_2$, to global median kabhi $X$ ke left half ya $Y$ ke right half mein nahi ho sakta. Un dono halves ko discard karo aur bache hue pe recurse karo!

Let $m_1 = ext{median}(X)$ and $m_2 = ext{median}(Y)$.

  • Case 1: $m_1 == m_2$: The global median is exactly $m_1$ (return immediately).
  • Case 2: $m_1 < m_2$: The global median must lie in $X[\lfloor n/2 floor .. n-1]$ or $Y[0 .. \lfloor n/2 floor]$. Discard $X[0 .. \lfloor n/2 floor - 1]$ and $Y[\lfloor n/2 floor + 1 .. n-1]$.
  • Case 3: $m_1 > m_2$: Symmetric discard: search in $X[0 .. \lfloor n/2 floor]$ and $Y[\lfloor n/2 floor .. n-1]$.
Step 2: Base Cases
  • If $n = 1$: return $(X[0] + Y[0]) / 2$.
  • If $n = 2$: return $(\max(X[0], Y[0]) + \min(X[1], Y[1])) / 2$.
Step 3: Complexity Recurrence
T(n) = T(n/2) + O(1) ==> T(n) = O(log n)
Q2.3. Digital Root of $4444^{4444} \pmod 9$
6 MARKS | ACTUAL PAPER REPEATING PATTERN
Problem: If $A = 4444^{4444}$, $B$ is the sum of digits of $A$, $C$ is the sum of digits of $B$, and $D$ is the sum of digits of $C$, compute the exact value of $D$.
💡 Asli Baat: Digital root ka golden rule: Kisi bhi number ka digital root $N \pmod 9$ ke barabar hota hai. Pehle $4444^{4444} \pmod 9$ nikaalo. Modulo 9 mein powers cycle karti hain. Phir upper bound lagao ki $D \le 12$, isliye $D$ uniquely 7 hi ho sakta hai!
Step 1: Digital Root Property Modulo 9

For any integer $N$, $N \equiv S(N) \pmod 9$ where $S(N)$ is the sum of decimal digits. Therefore:

A = 4444^4444 === B === C === D (mod 9)
Step 2: Base Reduction Modulo 9
4444 = 4 + 4 + 4 + 4 = 16 === 7 (mod 9) ==> 4444^4444 === 7^4444 (mod 9)
Step 3: Exponent Modular Cycle

Compute successive powers of $7 \pmod 9$:

7^1 = 7 === 7 (mod 9) 7^2 = 49 === 4 (mod 9) 7^3 = 7 · 4 = 28 === 1 (mod 9) <-- Cycle length (order) = 3

Reduce the exponent $4444$ modulo 3:

4444 = 3 · 1481 + 1 === 1 (mod 3)

Therefore:

4444^4444 === 7^4444 === 7^1 === 7 (mod 9) ==> D === 7 (mod 9)
Step 4: Strict Upper Bound on $D$
  • $A = 4444^{4444} < 10000^{4444} = (10^4)^{4444} = 10^{17776}$. Thus $A$ has at most 17,776 digits.
  • $B = S(A) \le 17,776 imes 9 = 159,984$.
  • Among all integers $\le 159,984$, the maximum digit sum occurs at $99,999$ (sum $= 45$) or $149,999$ (sum $= 37$). Hence $C = S(B) \le 45$.
  • Among integers $\le 45$, the maximum digit sum occurs at $39$ ($3 + 9 = 12$). Hence $D = S(C) \le 12$.
Step 5: Unique Determination

We know $D \equiv 7 \pmod 9$ and $1 \le D \le 12$. The only integer in this range is $D = 7$.

Q2.4. Popular Element ($\ge n/3$): Monte Carlo vs Las Vegas Derivation
6 MARKS | HIGH PROBABILITY PROBABILITY
Problem: An array of size $n$ contains an element that occurs at least $n/3$ times.
(a) Design a Monte Carlo algorithm that samples $m$ elements. Prove the minimum number of samples $m$ required so that the probability of error is at most $3^{-100}$.
(b) Design a Las Vegas algorithm and prove its expected running time is $O(n)$.
💡 Asli Baat: Monte Carlo mein fixed $m$ samples lete hain, error probability miss hone ki $\le (2/3)^m$ hoti hai. $(2/3)^m \le 3^{-100}$ ko solve karke exact $m \ge 271$ aata hai! Las Vegas mein check karte hain frequency, expected attempts $\le 3$ hoti hain to $E[T] = O(n)$!
Part (a): Monte Carlo Derivation

1. In each random pick, the probability of choosing the popular element is $p \ge rac{n/3}{n} = rac{1}{3}$.

2. The probability of missing the popular element in a single trial is $q = 1 - p \le rac{2}{3}$.

3. In $m$ independent samples with replacement, the probability that ALL $m$ samples miss is:

P(failure) = (2/3)^m

4. We require $P( ext{failure}) \le 3^{-100}$:

(2/3)^m ≤ 3^(-100) Taking natural logarithms on both sides: m · ln(2/3) ≤ -100 · ln 3 m · (ln 2 - ln 3) ≤ -100 · ln 3 m · (ln 3 - ln 2) ≥ 100 · ln 3 m · ln(1.5) ≥ 100 · ln 3 m ≥ (100 · ln 3) / ln(1.5)

5. Numerical evaluation:

ln 3 ≈ 1.098612 ==> 100 · ln 3 ≈ 109.8612 ln(1.5) ≈ 0.405465 m ≥ 109.8612 / 0.405465 ≈ 270.95

Hence, the minimum integer sample size is $m \ge 271$.

Part (b): Las Vegas Algorithm & Expected Time

1. Pick a random index $i \in [1..n]$ uniformly.

2. Count the frequency of $A[i]$ by scanning the array in $O(n)$ time.

3. If frequency $\ge n/3$, return $A[i]$ (always correct). Else repeat.

4. Probability of success per trial $p \ge 1/3$. The number of trials $X$ follows a Geometric Distribution with parameter $p$:

E[X] = 1 / p ≤ 1 / (1/3) = 3 trials E[Total Time] = E[X] · O(n) ≤ 3 · O(n) = O(n)
Q2.5. Josephus Problem: Recurrence, Closed Form & 1-Bit Cyclic Shift
6 MARKS | ACTUAL PAPER VERBATIM
Problem: $n$ people numbered $1$ to $n$ stand in a circle. Starting at person 1, every second person is eliminated until one person remains. Derive the recurrence relations for $J(2n)$ and $J(2n+1)$, prove the closed-form $J(2^m + l) = 2l + 1$, and explain the binary 1-bit cyclic shift property. Trace for $n = 41$.
💡 Asli Baat: Number ko $n = 2^m + l$ form mein likho. Power of 2 ($2^m$) ke aage jitne log $l$ bache hain, unka double $+ 1$ ($2l + 1$) survivor hota hai! Binary mein sirf leading bit ko utha kar end mein chipka do!
Step 1: Recurrence Derivation
  • Even $2n$: In the first round, all even numbers $2, 4, 6, \dots, 2n$ are eliminated. The remaining odd numbers are $1, 3, 5, \dots, 2n-1$. A person at position $k$ in the new circle corresponds to $2k - 1$ in the original circle. Thus:
    J(2n) = 2J(n) - 1
  • Odd $2n+1$: After eliminating $2, 4, \dots, 2n$, person 1 is eliminated next! The remaining people are $3, 5, 7, \dots, 2n+1$. A person at position $k$ in the new circle corresponds to $2k + 1$ in the original circle. Thus:
    J(2n+1) = 2J(n) + 1
Step 2: Closed Form Proof by Induction

Represent $n = 2^m + l$ where $2^m$ is the largest power of $2 \le n$, and $0 \le l < 2^m$.

J(2^m + l) = 2l + 1

Base Case: For $m=1, l=0$ ($n=2$): $J(2) = 2(0) + 1 = 1$, which holds.

Inductive Step:

  • If $l$ is even, $n = 2^m + l = 2(2^{m-1} + l/2)$. By even recurrence: $J(n) = 2J(2^{m-1} + l/2) - 1 = 2(2(l/2) + 1) - 1 = 2l + 1$.
  • If $l$ is odd, $n = 2(2^{m-1} + (l-1)/2) + 1$. By odd recurrence: $J(n) = 2J(2^{m-1} + (l-1)/2) + 1 = 2(2((l-1)/2) + 1) + 1 = 2l + 1$.
Step 3: Binary Cyclic Shift Representation

If $n$ is written in binary: $n = 2^m + l = (1 \, b_{m-1} \, b_{m-2} \, \dots \, b_0)_2$.

Notice that $l = (b_{m-1} \, b_{m-2} \, \dots \, b_0)_2$. Multiplying $l$ by 2 shifts bits left, and adding 1 appends 1 as LSB:

2l + 1 = (b_{m-1} \, b_{m-2} \, ... \, b_0 \, 1)_2

This is precisely a one-bit cyclic left shift of $n$!

Step 4: Trace for $n = 41$ (Historical Josephus Instance)
41 = 32 + 9 ==> 2^5 = 32, l = 9 J(41) = 2(9) + 1 = 19 Binary Verification: 41 = 101001_2 Cyclic left shift: 010011_2 = 16 + 2 + 1 = 19!

Q3.1. Catalan Recurrence: Matrix Chain Parenthesization & $\Omega(2^n)$ Proof
5 MARKS | HIGH FREQUENCY EXAM CORE
Problem: Let $f(n)$ be the number of ways to parenthesize a sequence of $n$ matrices.
(a) Derive the recurrence relation for $f(n)$ and state its base cases.
(b) Calculate the exact numerical values of $f(1), f(2), \dots, f(8)$.
(c) Formally prove by induction that $f(n) = \Omega(2^n)$.
💡 Asli Baat: $n$ matrices ko parenthesize karne ke liye last multiplication kisi split point $k$ ($1 \le k \le n-1$) par hoga. Left half mein $k$ matrices aur right mein $n-k$ matrices hongi. Isse Catalan recurrence $f(n) = \sum f(k)f(n-k)$ banti hai!
Part (a): Recurrence Derivation

To parenthesize $A_1 imes A_2 imes \dots imes A_n$, the final matrix multiplication splits the sequence into two subchains: $(A_1 \dots A_k) imes (A_{k+1} \dots A_n)$ for some split $k \in \{1, 2, \dots, n-1\}$.

f(n) = sum_{k=1}^{n-1} f(k) · f(n-k) for n ≥ 2, with base case f(1) = 1
Part (b): Exact Numerical Values ($n=1$ to $8$)
$n$ 1 2 3 4 5 6 7 8
Catalan $C_{n-1}$ $C_0 = \mathbf{1}$ $C_1 = \mathbf{1}$ $C_2 = \mathbf{2}$ $C_3 = \mathbf{5}$ $C_4 = \mathbf{14}$ $C_5 = \mathbf{42}$ $C_6 = \mathbf{132}$ $C_7 = \mathbf{429}$
Part (c): Proof that $f(n) = \Omega(2^n)$

Claim: $f(n) \ge 2^{n-2}$ for all $n \ge 2$.

Base Case: For $n=2$, $f(2) = 1 \ge 2^{2-2} = 2^0 = 1$. Holds.

Inductive Hypothesis: Assume $f(i) \ge 2^{i-2}$ holds for all $2 \le i \le n-1$.

Inductive Step: Consider the sum for $f(n)$:

f(n) = sum_{k=1}^{n-1} f(k) · f(n-k)

Keep only the two extreme terms $k=1$ and $k=n-1$:

f(n) ≥ f(1) · f(n-1) + f(n-1) · f(1) = 2 · f(1) · f(n-1)

Since $f(1) = 1$ and by inductive hypothesis $f(n-1) \ge 2^{(n-1)-2} = 2^{n-3}$:

f(n) ≥ 2 · 1 · 2^(n-3) = 2^(n-2)

Therefore $f(n) \ge 2^{n-2} = rac{1}{4} \cdot 2^n = \mathbf{\Omega(2^n)}$. (Exact closed form is $\Theta(4^n / n^{3/2})$).

Q3.2. Poisson Binomial DP: Exactly $k$ Heads from $n$ Biased Coins
5 MARKS | FORECAST DIVERSIFIED DP
Problem: Given $n$ biased coins with known success probabilities $p_1, p_2, \dots, p_n$, compute the exact probability of getting exactly $k$ heads ($0 \le k \le n$) in $O(nk)$ time and $O(k)$ space.
💡 Asli Baat: Normal binomial coefficient tabhi lagta hai jab coins fair ya identical hon. Yahan har coin ki probability $p_i$ alag hai! Isliye DP state $DP[i][j]$ = pehle $i$ coins mein $j$ heads aane ki probability. Coin $i$ ya to Head aayega ($p_i$) ya Tail ($1-p_i$)!
Step 1: State Definition & Recurrence

Let $DP[i][j]$ be the probability of getting exactly $j$ heads using the first $i$ coins ($1 \le i \le n, 0 \le j \le k$).

DP[i][j] = DP[i-1][j] · (1 - p_i) + DP[i-1][j-1] · p_i
Step 2: Base Cases & Constraints
  • $DP[0][0] = 1.0$ (0 coins produce 0 heads with probability 1).
  • $DP[0][j] = 0.0$ for all $j > 0$.
  • For $j = 0$: $DP[i][0] = DP[i-1][0] imes (1 - p_i) = \prod_{m=1}^i (1 - p_m)$.
Step 3: Space-Optimized $O(k)$ Implementation
double ProbabilityKHeads(vector& p, int n, int k): vector dp(k + 1, 0.0); dp[0] = 1.0; for (int i = 1; i <= n; i++): for (int j = min(i, k); j >= 1; j--): dp[j] = dp[j] * (1.0 - p[i-1]) + dp[j-1] * p[i-1]; dp[0] = dp[0] * (1.0 - p[i-1]); return dp[k];

Complexity: Time $O(nk)$, Auxiliary Space $O(k)$ (reverse iteration prevents overwriting).

Q3.3. Longest Arithmetic Progression Subsequence (LAPS) in $O(n^2)$
5 MARKS | TOP FORECAST ADVANCED DP
Problem: Given a sorted array $A[0..n-1]$ of distinct integers, design an $O(n^2)$ dynamic programming algorithm to find the length of the Longest Arithmetic Progression Subsequence (LAPS).
💡 Asli Baat: Kisi bhi Arithmetic Progression ka common difference fix karne ke liye 2 elements chahiye hote hain! Isliye DP state $DP[i][j]$ ko manenge "AP ending at $A[i]$ and $A[j]$". Middle element $i$ par 2-pointer chala kar $O(n^2)$ mein solve karte hain!
Step 1: DP State Formulation

Let $DP[i][j]$ be the length of the longest arithmetic progression whose last two elements are $A[i]$ and $A[j]$ (with $i < j$).

For any pair $(A[i], A[j])$, we search for an element $A[k]$ ($k < i$) such that:

A[j] - A[i] = A[i] - A[k] <===> A[k] + A[j] = 2 · A[i]
Step 2: DP Transition
DP[i][j] = DP[k][i] + 1 (if such k exists) DP[i][j] = 2 (base: any two elements form AP of length 2)
Step 3: Two-Pointer $O(n^2)$ Algorithm
int LongestAP(vector& A, int n): if (n <= 2) return n; vector> dp(n, vector(n, 2)); int max_len = 2; for (int i = 1; i < n - 1; i++): int k = i - 1, j = i + 1; while (k >= 0 && j < n): int sum = A[k] + A[j]; if (sum == 2 * A[i]): dp[i][j] = dp[k][i] + 1; max_len = max(max_len, dp[i][j]); k--; j++; else if (sum < 2 * A[i]): j++; // need larger element else: k--; // need smaller element return max_len;

Complexity: For each fixed $i$, pointers $k$ and $j$ make at most $n$ total moves. Total time = $\sum_{i=1}^{n-2} O(n) = \mathbf{O(n^2)}$. Space = $O(n^2)$.

Q3.4. Maximum Weight Independent Set on Trees (Tree DP)
5 MARKS | ACTUAL PAPER REPEATING PATTERN
Problem: Given a tree $T = (V, E)$ where each vertex $u$ has weight $w(u) \ge 0$, find an independent set of maximum total weight in $O(V)$ time.
💡 Asli Baat: Kisi bhi node $u$ ke paas 2 options hain: ya to $u$ ko select karo ya exclude karo. Agar $u$ ko include kiya to uske saare children EXCLUDE hone chahiye! Agar $u$ ko exclude kiya to children include ya exclude kuch bhi ho sakte hain!
Step 1: State Definition

Root the tree arbitrarily at node $r$. For each node $u$:

  • $DP[u][1]$: Maximum weight independent set in subtree at $u$, including $u$.
  • $DP[u][0]$: Maximum weight independent set in subtree at $u$, excluding $u$.
Step 2: Recurrence Relations
DP[u][1] = w(u) + sum_{v in children(u)} DP[v][0] DP[u][0] = sum_{v in children(u)} max(DP[v][0], DP[v][1])
Step 3: Algorithm & Linear Time Complexity

Perform a single Post-Order Traversal (DFS) from root $r$. Compute $DP[v][0]$ and $DP[v][1]$ for all children before evaluating parent $u$. Final answer is $\max(DP[r][0], DP[r][1])$.

Since every edge is traversed twice and every vertex is processed once, Time = $\mathbf{O(V)}$ and Space = $O(V)$.

Q4.3. Cut Property of Minimum Spanning Trees (MST)
5 MARKS | RIGOROUS PROOF CORE
Problem: State and formally prove the Cut Property of Minimum Spanning Trees. Use the exchange argument by contradiction.
💡 Asli Baat: Cut $(S, V \setminus S)$ ko cross karne wali sabse choti edge $e$ hamesha MST mein hogi. Agar assume karein ki nahi hai, to $e$ ko add karne par ek cycle banegi jismein ek aur cross edge $e'$ hogi. $e'$ ko hata kar $e$ daalne se strictly kam weight ka tree ban jayega, jo contradiction hai!
Step 1: Formal Statement

Let $G = (V, E, w)$ be a connected, undirected graph with real edge weights. Let $(S, V \setminus S)$ be any cut of $G$. If an edge $e = (u, v)$ is the strictly lightest edge crossing $(S, V \setminus S)$, then $e$ belongs to every Minimum Spanning Tree of $G$.

Step 2: Proof by Exchange Argument
  1. Suppose for contradiction that $T$ is an MST of $G$ and $e = (u, v) otin T$.
  2. Since $T$ is a spanning tree, adding $e$ to $T$ creates a unique cycle $C$.
  3. Because $u \in S$ and $v \in V \setminus S$, the cycle $C$ starts in $S$ and ends in $V \setminus S$, so it must cross the cut $(S, V \setminus S)$ at least once more via another edge $e' = (u', v') e e$.
  4. Consider the new subgraph $T' = T \cup \{e\} \setminus \{e'\}$.
  5. $T'$ remains connected and contains $|V|-1$ edges with no cycles; therefore $T'$ is a valid spanning tree.
  6. Compute the weight of $T'$:
    w(T') = w(T) + w(e) - w(e')
  7. Since $e$ is the strictly minimum weight edge crossing the cut, $w(e) < w(e')$, which implies:
    w(T') < w(T)
  8. This contradicts the optimality of $T$ as a Minimum Spanning Tree!
  9. Hence, our initial assumption was false, and $e \in T$. $lacksquare$

Q5.1. Max-Flow Min-Cut Theorem: Formal Statement & Rigorous Proof
6 MARKS | RECURRING THEORETICAL PILLAR
Problem: State the Max-Flow Min-Cut Theorem. Prove that the value of any feasible flow is bounded by the capacity of any cut, and prove that max flow equals min cut when no augmenting path remains in the residual network $G_f$.
💡 Asli Baat: Kisi bhi pipe network mein flow source se sink tak jata hai. Har cut $(S, T)$ ek bottleneck hai. Jab Ford-Fulkerson rukta hai to residual graph mein $s$ se reachable nodes ka set $S^*$ banta hai. Is cut par har forward edge full hoti hai aur har backward edge zero, isliye $|f| = c(S^*, T^*)$!
Step 1: Definitions & Cut Capacity

An $(S, T)$-cut partitions $V$ such that $s \in S$ and $t \in T$. The capacity of the cut is:

c(S, T) = sum_{u in S, v in T} c(u, v)
Step 2: Lemma — Net Flow Across Cut Equals Total Flow

By flow conservation at all vertices $u \in S \setminus \{s\}$:

|f| = f(S, T) = sum_{u in S, v in T} f(u, v) - sum_{u in T, v in S} f(u, v)

Since $f(u, v) \le c(u, v)$ and $f(v, u) \ge 0$, we immediately obtain Weak Duality:

|f| ≤ sum_{u in S, v in T} c(u, v) = c(S, T) (Flow <= Capacity of ANY Cut)
Step 3: Equality at Maximum Flow (Strong Duality)

Let $f^*$ be a flow such that the residual graph $G_{f^*}$ contains no augmenting path from $s$ to $t$.

Define $S^* = \{v \in V \mid ext{there exists a path from } s ext{ to } v ext{ in } G_{f^*}\}$ and $T^* = V \setminus S^*$.

  • $s \in S^*$ (trivially reachable from itself).
  • $t \in T^*$ (otherwise an augmenting path exists from $s$ to $t$, contradicting termination).

For any edge $(u, v)$ with $u \in S^*$ and $v \in T^*$:

  • We must have $c_f(u, v) = 0$, otherwise $v$ would be reachable from $u$, putting $v \in S^*$.
  • Since $c_f(u, v) = c(u, v) - f^*(u, v) = 0 \implies \mathbf{f^*(u, v) = c(u, v)}$ (all forward edges saturated).
  • For any edge $(v, u)$ with $v \in T^*$ and $u \in S^*$, $c_f(v, u) = f^*(v, u) = 0 \implies \mathbf{f^*(v, u) = 0}$.

Substitute these into the net flow equation:

|f*| = f(S*, T*) = sum_{u in S*, v in T*} c(u, v) - 0 = c(S*, T*)

Since $|f| \le c(S, T)$ for all cuts and $|f^*| = c(S^*, T^*)$, the flow $f^*$ is maximal and $(S^*, T^*)$ is the minimum cut! $lacksquare$

Q5.2. Maximum Bipartite Matching via Max-Flow Reduction
5 MARKS | STANDARD REDUCTION CORE
Problem: Given a bipartite graph $G = (L \cup R, E)$, formally reduce the Maximum Bipartite Matching problem to Maximum Flow. Prove correctness using the Integrality Theorem.
💡 Asli Baat: Bipartite graph mein $s$ aur $t$ add karo. $s o L$ edges capacity 1 ki banao, $L o R$ capacity 1 ki, aur $R o t$ capacity 1 ki. Integrality theorem guarantee karta hai ki flow integer (0 ya 1) aayega, jisse unit flow edges directly valid maximum matching ban jayengi!
Step 1: Network Construction
  1. Construct flow network $G' = (V', E', c)$ where $V' = L \cup R \cup \{s, t\}$.
  2. Add directed edge $(s, u)$ for every $u \in L$ with capacity $c(s, u) = 1$.
  3. Add directed edge $(u, v)$ for every undirected edge $\{u, v\} \in E$ ($u \in L, v \in R$) with capacity $c(u, v) = 1$.
  4. Add directed edge $(v, t)$ for every $v \in R$ with capacity $c(v, t) = 1$.
Step 2: Correctness Proof via Integrality Theorem
  • Integrality Theorem: Since all capacities are integral (all 1s), Ford-Fulkerson outputs an integral maximum flow $f^*$ where $f^*(e) \in \{0, 1\}$.
  • Valid Matching: Let $M = \{(u, v) \in E \mid f^*(u, v) = 1\}$.
    • Each $u \in L$ has only one incoming edge from $s$ with capacity 1 $\implies$ at most one outgoing edge from $u$ carries flow $\implies$ $u$ is matched at most once.
    • Each $v \in R$ has only one outgoing edge to $t$ with capacity 1 $\implies$ at most one incoming edge into $v$ carries flow $\implies$ $v$ is matched at most once.
    • Hence $M$ is a valid matching of size $|M| = |f^*|$.
  • Maximality: Any matching of size $k$ can be turned into a valid flow of value $k$. Thus max flow $\iff$ max matching.

Complexity: $O(V' \cdot E') = \mathbf{O(V E)}$ using Ford-Fulkerson.

  • NP-Complete: A problem $B$ is NP-Complete iff $B \in ext{NP}$ and $B \in ext{NP-Hard}$.

Q6.2. 3-SAT to CLIQUE / Vertex Cover Reduction Proof
5 MARKS | ACTUAL PAPER REPEATING PATTERN
Problem: Prove that CLIQUE is NP-Complete by showing a polynomial-time reduction from 3-SAT.
💡 Asli Baat: 3-SAT formula mein $k$ clauses hain. Har clause ke 3 literals ke liye 3 vertices banao (gadgets). Edges unhi do vertices ke beech lagao jo ALAG clauses mein hon aur aapas mein CONFLICT na karte hon ($x$ and $ eg x$ na hon). 3-SAT satisfiable tabhi hoga jab graph mein size $k$ ka CLIQUE hoga!
Step 1: Gadget Construction

Given 3-SAT formula $\phi = C_1 \wedge C_2 \wedge \dots \wedge C_k$ with clauses $C_r = (l_{r1} ee l_{r2} ee l_{r3})$:

  • Construct graph $G = (V, E)$ where for each clause $C_r$, create 3 vertices representing its literals. Total $|V| = 3k$.
  • Add an undirected edge between vertex $u$ in $C_r$ and vertex $v$ in $C_s$ ($r e s$) if and only if $u$ and $v$ are from different clauses and are NOT negations of each other ($u e eg v$).
Step 2: Correctness Proof in Both Directions
  • ($\implies$ Direction): Suppose $\phi$ is satisfiable. In a satisfying assignment, pick one literal that evaluates to TRUE in each clause $C_1, \dots, C_k$. This gives a set $S$ of $k$ vertices. Since all $k$ literals are TRUE, no two can be negations of each other ($u e eg v$), and all are from different clauses. By construction, there is an edge between every pair of vertices in $S$. Thus $S$ forms a clique of size $k$.
  • ($\impliedby$ Direction): Suppose $G$ contains a clique $S$ of size $k$. Since no edges exist between vertices in the same clause, $S$ must contain exactly one vertex from each of the $k$ clauses. Furthermore, since edges only connect non-conflicting literals, no two vertices in $S$ represent $x$ and $ eg x$. Assign TRUE to all literals in $S$ (and arbitrary truth values to remaining variables). Every clause now has at least one TRUE literal. Thus $\phi$ is satisfiable!

Since construction takes $O(k^2)$ time, 3-SAT $\le_p$ CLIQUE. $lacksquare$

Q6.3. Vertex Cover 2-Approximation Algorithm via Maximal Matching
5 MARKS | FORECAST APPROXIMATION CORE
Problem: Describe the maximal matching-based 2-approximation algorithm for the Minimum Vertex Cover problem. Formally prove that the approximation ratio is at most 2. Show a tight example.
💡 Asli Baat: Koi bhi edge $(u, v)$ pakdo, DONO vertices ko cover set $C$ mein daal do, aur unse jude saare edges delete kar do. Yeh edges ek matching $M$ banate hain. Har optimal cover $C^*$ ko is matching ke har edge se kam se kam 1 vertex lena padega ($|C^*| \ge |M|$). Humne dono endpoints liye to $|C| = 2|M| \le 2|C^*|$!
Step 1: Algorithm Description
Algorithm ApproxVertexCover(G = (V, E)): C = empty_set E_prime = E while E_prime is not empty: pick an arbitrary edge (u, v) in E_prime C = C union {u, v} remove from E_prime all edges incident to u or v return C
Step 2: Formal Proof of Approximation Ratio $\le 2$
  1. Let $M$ be the set of edges selected in the while-loop. By definition of the algorithm, whenever an edge $(u, v)$ is chosen, all incident edges are removed. Hence, no two edges in $M$ share a common endpoint. Thus $M$ is a valid matching.
  2. Any valid vertex cover $C^*$ must cover every edge in $M$. Since all edges in $M$ are vertex-disjoint, no single vertex can cover more than one edge in $M$. Therefore:
    |C*| ≥ |M|
  3. For each edge in $M$, our algorithm adds both endpoints to $C$. Therefore:
    |C| = 2 |M|
  4. Combining these inequalities:
    |C| = 2 |M| ≤ 2 |C*|

Hence the algorithm achieves an approximation ratio of 2 and runs in linear time $O(V + E)$.

Step 3: Tight Example

A graph consisting of disjoint edges $K_2$ (e.g., $E = \{(v_1, v_2), (v_3, v_4)\}$). An optimal cover picks 1 vertex per edge ($|C^*| = 2$), while the algorithm picks both endpoints ($|C| = 4$). The ratio is exactly $ rac{4}{2} = 2$.

Q6.4. Planar Red & Blue Points: Non-Crossing Segment Matching Proof
5 MARKS | ACTUAL PAPER GEOMETRIC PROOF
Problem: Given $n$ red points and $n$ blue points in general position in the 2D plane (no three points collinear), prove that there exists a one-to-one matching between red and blue points such that the straight line segments connecting matched pairs do not intersect each other.
💡 Asli Baat: Finite matchings ($n!$) mein se wo matching $M^*$ choose karo jismein segments ki total Euclidean length MINIMUM ho! Agar assume karein ki 2 segments aapas mein cross kar rahe hain, to triangle inequality se endpoints swap karne par total length aur choti ho jayegi, jo contradiction hai!
Step 1: Set of Possible Bijections

Let $R = \{r_1, r_2, \dots, r_n\}$ be the red points and $B = \{b_1, b_2, \dots, b_n\}$ be the blue points. There are $n!$ possible bijective matchings $\pi: R o B$.

For any matching $\pi$, define its total Euclidean length as:

L(pi) = sum_{i=1}^n ||r_i - b_{pi(i)}||
Step 2: Existence of Minimal Length Matching

Since the number of permutations $n!$ is finite and positive, there must exist at least one matching $\pi^*$ that achieves the global minimum total length $L(\pi^*)$.

Step 3: Proof by Contradiction via Triangle Inequality
  1. Suppose for contradiction that under $\pi^*$, two line segments intersect. Without loss of generality, let $(r_1, b_1)$ and $(r_2, b_2)$ cross at point $X$.
  2. In $ riangle r_1 X b_2$, by the strict Triangle Inequality (points in general position):
    ||r_1 - b_2|| < ||r_1 - X|| + ||X - b_2||
  3. In $ riangle r_2 X b_1$, by the strict Triangle Inequality:
    ||r_2 - b_1|| < ||r_2 - X|| + ||X - b_1||
  4. Adding these two strict inequalities together:
    ||r_1 - b_2|| + ||r_2 - b_1|| < (||r_1 - X|| + ||X - b_1||) + (||r_2 - X|| + ||X - b_2||) = ||r_1 - b_1|| + ||r_2 - b_2||
  5. Now consider an alternative matching $\pi'$ that uncrosses these two segments by pairing $(r_1, b_2)$ and $(r_2, b_1)$, keeping all other pairs unchanged.
  6. The total length of $\pi'$ is:
    L(pi') = L(pi*) - (||r_1 - b_1|| + ||r_2 - b_2||) + (||r_1 - b_2|| + ||r_2 - b_1||) < L(pi*)
  7. This contradicts the assumption that $\pi^*$ was the minimum length matching!

Therefore, the minimum length matching $\pi^*$ cannot contain any intersecting segments. $lacksquare$
